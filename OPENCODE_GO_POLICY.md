# Политика использования OpenCode Go

Документ фиксирует ограничения подписки OpenCode Go ($10/мес) и правила для этого проекта.
Источники: документация OpenCode (Go, Harnesses, Inference API) и Terms of Use от 15.08.2026.

## Что разрешено

- Использовать Go как провайдера coding-агента: Kilo Code CLI, OpenCode, Claude Code, Codex, Hermes, Pi и аналогичных клиентов.
- Отправлять типичный трафик coding-агента: чтение файлов, правки, запуск тестов, обсуждение кода.
- Указывать собственный `User-Agent` клиента и стабильный `x-opencode-session` на диалог.

## Что запрещено

- Направлять в Go трафик приложений, игр, чат-ботов и ассистентов, включая DnD-мастера и backend этого проекта.
- Подключать Go-ключ к `LLM_BASE_URL` приложения, скриптам, cron-задачам и любым автоматическим генерациям.
- Использовать Go для разовых «проверок работоспособности» не-code задач.
- Создавать несколько аккаунтов или иным способом обходить лимиты, региональные и иные ограничения.
- Выдавать сгенерированный текст за созданный человеком, извлекать данные автоматически, создавать нагрузку, мешающую другим пользователям.

Формулировки OpenCode: сервис «designed for OpenCode and other coding agents that produce similar types of requests»,
клиент должен «send typical coding agent traffic», трафик «monitored for abuse». Terms of Use запрещают использование
«for any purpose not reasonably intended by OpenCode». FAQ прямо говорит: приложения без coding-сессии должны
использовать pay-as-you-go, а не Go.

## Что делать при запросе нарушить эти правила

1. Сразу сообщить пользователю, что задача не относится к coding-трафику и Go для неё использовать нельзя.
2. Не выполнять запрос, пока пользователь не выберет альтернативу.
3. Предложить варианты:
   - локальная Ollama: `http://localhost:11434/v1`, модель `qwen3:14b` (уже настроена в `backend/.env`);
   - обычный облачный OpenAI-совместимый провайдер;
   - pay-as-you-go OpenCode Console (`https://opencode.ai/inference/openai/v1`) с оговоркой, что это отдельный биллинг и тоже только для внутренних задач.
4. Если пользователь подтвердил альтернативу, делегировать задачу локальной модели, а не Go.

## Технические гарантии в проекте

Что выполнено сейчас:

- В `backend/.env` настроена локальная модель Ollama, ключей OpenCode там нет и быть не должно.
- `backend/app/core/config.py` при старте отклоняет `LLM_BASE_URL` на Go-эндпоинты
  (`/zen/go`, `/inference/go`) с понятной ошибкой; поведение покрыто `backend/tests/test_config.py`.
- Defaults в `config.py` указывают на локальную Ollama (`http://localhost:11434/v1`),
  поэтому без `.env` приложение не выбирает платный облачный endpoint.
- Pay-as-you-go endpoint (`/inference/openai/v1`) не блокируется: это отдельный биллинг,
  и для трафика приложения его можно выбрать только осознанно.
- Скрипты, тесты и `start.bat` не обращаются к Go-эндпоинтам.

Что остаётся на ручную проверку:

- `git grep -i "opencode.ai"` теперь находит строки в самой блокировке, тестах и
  документации — это ожидаемо. Проверяйте, что Go-URL нет в `backend/.env`, frontend,
  скриптах и коде провайдера, кроме `config.py` и его тестов.
- Автоматическая проверка не отличает злонамеренно замаскированный URL (например,
  через прокси). Перед запуском сверяйте `LLM_BASE_URL` в `backend/.env` глазами.
