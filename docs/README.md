# Документация проекта

Одна страница о том, какой документ для кого и когда его читать.

## Карта документов

| Документ | Для кого | Статус | Когда читать |
|---|---|---|---|
| [`AGENTS.md`](../AGENTS.md) | coding-агент | актуален | всегда, это точка входа |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | coding-агент | актуален, сверен с кодом | перед задачами про API, БД, prompt, retrieval, конфиг, тесты |
| [`human/ARCHITECTURE_GUIDE_2026.md`](human/ARCHITECTURE_GUIDE_2026.md) | человек | актуален как учебник | когда нужно понять проект целиком или объяснить термин |
| [`../backend/README.md`](../backend/README.md) | человек | актуален | пошаговый локальный запуск, Ollama, импорт SRD, API |
| [`../OPENCODE_GO_POLICY.md`](../OPENCODE_GO_POLICY.md) | человек и агент | актуален как политика | перед любым вопросом про провайдера/OpenCode Go |
| [`../kilo.json`](../kilo.json) | Kilo | актуален | права на `.env`: чтение разрешено, изменение — с подтверждением |
| [`archive/ARCHITECTURE_GUIDE_legacy.md`](archive/ARCHITECTURE_GUIDE_legacy.md) | история | устарел | только для истории, не источник истины |
| `.kilo/plans/*.md` | история задач | завершены | только если нужно восстановить контекст старой задачи |

Правило: **у каждого факта один канонический дом**. Архитектурные факты — в
`docs/ARCHITECTURE.md`, команды и правила работы — в `AGENTS.md`, пошаговый запуск —
в `backend/README.md`, политика провайдера — в `OPENCODE_GO_POLICY.md`.
Не дублируй большие блоки между ними: лучше ссылка.

## Что агенту читать не нужно

- `docs/human/**` — длинный учебник, написанный для человека;
- `docs/archive/**` — устаревшие версии;
- `backend/data/srd/srd-5.2.1.md` — корпус данных (~1.6 МБ), а не документация;
- `.kilo/plans/**` — исторические планы, кроме плана текущей задачи.

Эти ограничения записаны и в `AGENTS.md`, чтобы агент не тратил контекст.
`backend/.env` читать можно (см. ниже), но не стоит без необходимости.

## Права на `.env`

Правила заданы в двух местах:

- [`kilo.json`](../kilo.json) в проекте: чтение `.env` разрешено, изменение — `ask`,
  shell-команды, упоминающие `.env`, — `ask`;
- глобальный `~/.config/kilo/kilo.jsonc`: дополнительно разрешает чтение
  `D:\Dev\dnd_master\*.env`, если Kilo запущен из другой папки, а проект открыт
  как внешний.

Это техническая страховка, а не разрешение менять файл молча. По `AGENTS.md` агент
обязан сначала объяснить, какой ключ и зачем меняется, и дождаться подтверждения.
Изменения конфигурации прав применяются к новым сеансам.

## Как ставить задачу агенту

Коротко и в терминах результата:

1. Что сделать и зачем (одно-два предложения).
2. Какие файлы/модули затрагиваются, если известно.
3. Что считается готовым: поведение, тесты, проверки.
4. Ограничения: не менять API/схему, не менять `.env` без разрешения, не коммитить и т.п.

Если задача большая — разбей на шаги и попроси сначала план. Агент сам подтянет
`AGENTS.md` и `docs/ARCHITECTURE.md`; не нужно вставлять архитектуру в каждое сообщение.

## Как поддерживать порядок

- Меняешь API, схему БД, конфиг, prompt или инварианты — обнови `docs/ARCHITECTURE.md`.
- Не создавай новые `*.md` в корне: для агента — `docs/`, для человека — `docs/human/`,
  устаревшее — `docs/archive/`.
- Устаревший документ не удаляй молча: перенеси в `docs/archive/` и добавь в начало
  пометку «АРХИВ. УСТАРЕЛО» с указанием актуального файла.
- Большие учебники и инструкции для человека держи вне корня и вне пути, который агент
  читает по умолчанию.
- Если документ и код разошлись, правь документ, а не подгоняй код под документ
  (кроме случаев, когда расхождение — баг в коде).
